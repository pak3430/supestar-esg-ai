# 수페스타 질문 처리·위험 게이트 매트릭스

- 기준일: 2026-08-25 KST
- 적용 대상: 수페스타 로컬 웹 Runtime, 대화 이력 격리 검증 profile v5
- 목적: 자연어 질문이 원자 Skill 입력으로 잘못 변환되거나, AI 문장이 검증 판정보다 앞서 결론을 단정하는 재발을 막는다.

## 1. 답변이 만들어지는 기준

```text
현재 질문
→ 기본 독립 처리 / 명시적 참조가 있으면 직전 사용자 질문 1개만 연결
→ 현재 질문의 주된 의도 1개 선택
→ 사용자 진술에서만 구조화 필드 추출
→ 상충·부정·누락 검사
→ Runtime Composite 단일 진입
→ 관련 Identity와 Goal → Task → Knowledge → Method → Skill 실행
→ 결정론적 PROCEED / REVIEW / STOP
→ 허용되는 경우에만 로컬 AI가 자연어로 표현
→ Output Risk Gate가 판정·주장·권한·링크를 다시 검사
→ 사용자 답변 + 실행 증거 저장
```

로컬 AI는 분류기나 최종 판단자가 아니다. 원자 Skill이 확정한 경로·후보·누락·판정을 바꾸지 않는 표현 계층이다.

## 2. 질문군별 처리 원칙

| 질문군 | 충분한 입력 | 부족·상충 입력 | 금지·고위험 요청 |
| --- | --- | --- | --- |
| ESG·SDGs·KAC·기관·등록부 개념 | 선택된 Concept KAC로 직접 설명 | 지원 개념이 불분명하면 `REVIEW` | 프롬프트 공개·근거 조작은 `STOP` |
| ESG → 탄소 행동경로 | 측정→감축→잔여배출→보완 순서 설명 | 조직의 실제 시장 판단인데 측정 맥락이 없으면 `REVIEW` | 측정·직접감축을 건너뛴 탄소중립 확정은 `STOP` |
| Scope 분류 | 활동·조직경계·소유통제/구매에너지/가치사슬 관계가 한 후보를 가리키면 `PROCEED` | 관계 누락, 여러 활동 혼합, 상충이면 `REVIEW` | 검증 후보와 다른 Scope 단정은 출력 단계에서 폐기 |
| CCM·VCM·배출권·크레딧 | 학습 비교 또는 확인된 목적·등록상태면 규칙에 따라 설명 | 등록·소각·사용 상태 미확인, 외부 주장은 `REVIEW` | 이중사용, 실제 구매·이전·소각은 `STOP` |
| 산림 E/S/G | 사용자 진술상 E·S·G 자료가 모두 있으면 매핑 | 한 축이라도 없으면 해당 축을 표시하고 `REVIEW` | 권리·지역사회·거버넌스를 숨긴 완결 주장은 `STOP` |
| 산림탄소 절차 | 사업유형·현재단계·현재단계 증빙이 있으면 다음 단계 안내 | 현재단계 누락·복수 단계 상충·증빙 누락은 `REVIEW` | 선행 검증·인증 없이 거래 가능 확정은 `STOP` |
| 거래 준비도 | G1~G11 사용자 입력이 모두 통과하면 준비도만 `PROCEED` | 비차단 검토 게이트가 남으면 `REVIEW` | 핵심 게이트 누락은 `STOP`; 모델 생성은 상태와 무관하게 항상 차단 |

## 3. 재발 가능 상황과 방어 방식

| 상황 | 잘못된 동작 | 현재 방어 |
| --- | --- | --- |
| 구체적인 배출원 문장인데 구조화 필드가 비어 있음 | Skill은 `REVIEW`, AI는 임의로 Scope 단정 | 자연어→타입 필드 추출 후 동일 입력으로 Skill 실행 |
| “회사 소유가 아니다” | `회사 소유` 문자열만 보고 Scope 1 오판 | 부정 소유 표현을 먼저 판별하고 소유 관계를 `NOT_OWNED_CONTROLLED`로 유지 |
| 보일러와 구매전력이 한 질문에 섞임 | 한 Scope를 임의 선택 | 후보 관계 충돌을 기록하고 모두 `UNKNOWN`, 결과 `REVIEW` |
| 등록 완료 후 소각 완료 | 두 상태를 무조건 충돌로 처리 | 정상 생명주기 `REGISTERED→TRANSFERRED→RETIRED`는 최신 상태 인정 |
| 등록 완료지만 소각 여부 미확인 | 등록 완료만 보고 사용 가능 오판 | 확인 상태와 `UNVERIFIED`가 함께 있으면 충돌로 기록하고 `REVIEW` |
| 보고서는 보유, 동의서는 미보유 | 한 부정문 때문에 모든 문서를 미보유 처리 | 각 문서가 들어 있는 문장 단위로 보유·미보유 판별 |
| 짧은 새 질문 | 이전 배출원 관계를 자동 상속 | 길이는 후속 질문 조건에서 제외; “그 배출원” 같은 명시 참조만 상속 |
| ESG 다음 “SDGs는요?” | 짧다는 이유로 ESG와 합쳐 ESG를 다시 답함 | 현재 질문을 독립 처리하고 `SUSTAINABLE_DEVELOPMENT_GOALS`만 선택 |
| “그러면 SDGs는요?” | 접속사만 보고 직전 ESG를 강제 상속 | “그러면”은 단독 참조로 보지 않고 SDGs 새 주제로 처리 |
| “그건 왜 중요한가요?” | 참조 대상을 잃어 일반 답변 또는 엉뚱한 주제 답변 | 명시적 지시어를 확인해 직전 사용자 질문 1개만 라우터·KAC·Context·AI에 공통 전달 |
| 이전 AI 답변이 잘못된 사실을 말함 | 다음 판정의 사실 입력으로 재사용 | Context와 AI 생성 모두 이전 assistant 발화를 사실 근거에서 제외 |
| 사업등록 단계와 모니터링 단계를 동시에 주장 | 높은 단계를 임의 선택 | 복수 현재단계를 충돌로 기록하고 `currentStage=UNKNOWN`, 결과 `REVIEW` |
| Scope Skill은 `REVIEW`, 모델은 Scope 1 설명 | 사용자는 모델 문장을 최종 결과로 오인 | 모든 `REVIEW/STOP`에서 모델 생성 차단, 검증된 보완 질문만 표시 |
| 모델이 후보와 다른 Scope를 말함 | 결정론적 판정 변조 | 모델 문장 속 Scope 라벨을 후보와 대조하고 불일치 시 전체 생성문 폐기 |
| 모델이 공식 인증·법적 유효·거래 완료를 주장 | 권한을 넘어선 확정 | 공식성·법률·세무·거래·등록 변경 패턴을 차단하고 구조화 답변으로 복귀 |
| 일반 ESG 질문에 마켓 링크 노출 | 답변이 홍보로 변질 | 명시적인 구매처·구매 방법 질문 한정으로 링크 허용 |
| 오늘 가격·실시간 시세·투자추천 | 로컬 지식으로 최신값을 꾸밈 | `OUT_OF_SCOPE/STOP`; 모델 호출 없음 |
| 배출계수 없는 tCO2e 확정 계산 | 숫자를 추정해 계산 | 계산 실행 범위 밖으로 차단하고 필요한 공식 계수 확인을 요청 |
| 이전 지시 무시·시스템 프롬프트 공개 | 안전·근거 경계 우회 | 라우터에서 `OUT_OF_SCOPE/STOP`, 모델 호출 없음 |
| 검증 없이 증빙 생성 | 가짜 근거를 실행 입력으로 승격 | 근거 조작 요청을 `STOP`; 사용자 진술과 실제 원문 기록을 분리 |

## 4. 검증된 Scope 자연어 유형

- Scope 1: 소유·통제 보일러, 영업 차량, 냉매 누출 등 직접 배출원
- Scope 2: 구매 전력, 구매 스팀, 구매 열, 구매 냉방
- Scope 3 상류: 구매 원재료·구매품, 외주 운송, 출장, 통근, 폐기물, 자본재, 상류 임차자산
- Scope 3 하류: 판매제품 사용·가공·폐기, 하류 운송·임차자산, 프랜차이즈, 투자 배출
- 보수적 `REVIEW`: 외부 소유라는 사실만 있고 상·하류 관계가 없는 경우, 서로 다른 Scope 활동이 한 질문에 섞인 경우

## 5. 출력 모드

- `LOCAL_AI_GROUNDED`: `PROCEED`이며 고위험 거래 경로가 아니고, 모델 결과가 Output Risk Gate를 통과한 경우
- `STRUCTURED_GROUNDED`: 모델 미연결, 생성 실패, 생성문 위험, `REVIEW/STOP`, 거래 준비도 경로 중 하나에 해당하는 경우
- 어느 모드에서도 Identity·KAC·원자 Skill 결과와 Run Record는 동일하게 생성된다.

## 7. 남아 있는 경계

자연어의 모든 문장을 문자열 규칙만으로 완전하게 해석할 수 있다고 주장하지 않는다. 현재 Runtime은 지원 질문군과 검증된 표현을 넓히되, 새 표현이 명확히 매핑되지 않으면 임의 결론 대신 `REVIEW`한다. 새로운 오판 사례가 발견되면 질문 fixture를 먼저 추가하고, 추출 규칙·판정·출력 게이트를 수정한 뒤 전체 회귀 검증을 다시 통과해야 한다.
