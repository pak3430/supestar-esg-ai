# 수페스타 최종 발표 구성안

- 기준일: 2026-08-25
- 분량: 11장
- 중심 문장: 수페스타는 KAC 지식을 질문별로 선택하고 연결된 Skill을 실행한 뒤, 로컬 AI가 검증 결과만 설명하는 스킬 실행형 ESG 챗봇이다.

## 장표 구성

| 장 | 제목 | 반드시 보여줄 것 |
| ---: | --- | --- |
| 1 | 수페스타 | 제품명, 브라우저형 ESG 대화 MVP, 팀 초 ROK |
| 2 | 문제는 정보가 아니라 다음 행동 | 시민·기업·산주의 실제 질문과 일반 챗봇의 한계 |
| 3 | 정확히 무엇을 만드는가 | 질문 → 쉬운 답 → 이유 → 지금 할 일 → 필요할 때 기술 증거 |
| 4 | 왜 KAC인가 | Identity → Goal → Task → Knowledge → Method → Skill, 구조화·묶음·배포 이유 |
| 5 | 실제 실행 구조 | Context → Composite → KAC → Run Skill → Local AI → Output Gate |
| 6 | 시연 A: 일반 ESG 질문 | ESG 질문에는 ESG만 답하고 마켓 링크가 없음을 화면으로 증명 |
| 7 | 시연 B: 구체 Scope 질문 | 사용자 문장을 타입 필드로 만들고 `PROCEED / SCOPE_1`을 반환 |
| 8 | 시연 C: 상충 질문 | 보일러와 구매전력을 섞으면 `REVIEW`, AI 생성 차단, 자연스러운 보완 질문 |
| 9 | 필요할 때만 실제 행동 연결 | 명시적 구매처 질문에서만 산림탄소마켓 제시 |
| 10 | 구현·검증·책임성 | 23 tests, 60 scenarios, 8 local-AI cases, 9 routes, PROCEED·REVIEW·STOP, Run Record |
| 11 | 결론 | AI가 판단을 꾸미지 않고 지식·Skill·사람의 책임을 연결한다는 메시지 |

## 발표 흐름

1. “ESG가 무엇인지”보다 “내 상황에서 무엇을 해야 하는지”가 더 어렵다는 문제를 제시한다.
2. 수페스타가 브라우저 챗봇이라는 제품 형태를 먼저 명확히 말한다.
3. 일반 RAG와 다른 KAC·Skill 실행 구조를 도식으로 설명한다.
4. 일반 질문, 충분한 구체 질문, 상충 질문을 연속으로 보여준다.
5. 마켓은 모든 답변의 목적지가 아니라 명시적 구매 의도에서만 제공되는 외부 선택지임을 보여준다.
6. 기술 검증과 남은 책임 경계를 함께 제시한다.

## 금지 표현

- “모든 ESG 질문을 산림탄소마켓으로 연결한다.”
- “챗봇 전체가 Stage Skill만으로 자동 생성됐다.”
- “AI가 거래·인증·공시를 승인한다.”
- “외부 인터넷을 실시간 검색해 답한다.”
- “60개 시나리오로 모든 자연어 질문을 해결했다.”

## 발표자 핵심 답변

### 지식 데이터를 쓰는 챗봇인가, Skill로 만들어진 챗봇인가

둘 다 포함하지만 중심은 Skill 실행이다. 질문별 KAC 파일을 근거로 선택하고, 연결된 Run Skill이 판정과 산출물을 실제로 만든다. 웹·서버·Context 추출·출력 게이트는 그 Skill을 안전하게 서비스하는 별도 Runtime이다.

### 로컬 AI는 무엇을 하는가

검증된 결과를 자연스럽게 표현한다. 경로·후보·판정·근거를 결정하거나 바꾸지 않는다. `REVIEW/STOP`과 거래 준비도에서는 자유 생성을 차단한다.

### 산림탄소마켓은 왜 나오는가

사용자가 실제 구매처·구매 방법을 물었을 때만 제공하는 외부 행동 선택지다. ESG 설명의 기본 목적지나 홍보 CTA가 아니다.
